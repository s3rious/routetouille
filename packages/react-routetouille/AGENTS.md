## Code Style

### Naming Conventions

- Hooks: `use` prefix (e.g., `useRouterRoot`, `useLink`)
- HOCs: `With` prefix (e.g., `WithReactComponent`)
- Strategies: `render` prefix (e.g., `renderTree`)

### TypeScript Rules

- **IMPORTANT**: Strict mode - no implicit any
- **IMPORTANT**: Never use `any` - use `unknown` with type guards
- Use proper generics for hook return types

## Core Concepts

### Hooks

```typescript
// Primary integration hook
const { router, active } = useRouterRoot(router);

// Navigation
const { href, onClick } = useLink({ to: 'route-name', params: {} });
const goTo = useGoTo();
const router = useRouter();
```

### Rendering Strategies

| Strategy | Use Case |
|----------|----------|
| `renderTree` | Standard nested layouts |
| `renderLastActive` | Single component (modals) |
| `renderLastExclusiveAndTree` | Layout boundaries (auth sections) |

### Route Enhancement

```typescript
// Add React component to route
WithReactComponent(Route)({
  name: 'dashboard',
  path: '/dashboard',
  component: DashboardComponent,
  exclusive: true, // Creates rendering boundary
});
```

## Patterns to Follow

- **Hooks**: `src/hooks/useRouterRoot.ts`
- **HOCs**: `src/Route/WithReactComponent/WithReactComponent.ts`
- **Tests**: `src/hooks/useLink.test.ts`

## Anti-Patterns to Avoid

| Don't | Do Instead |
|-------|------------|
| Use `any` type | Use `unknown` with type guards |
| Skip `exclusive` for layout switches | Mark layout boundaries as `exclusive: true` |
| Create context without router | Always pass router to `useRouterRoot` first |
