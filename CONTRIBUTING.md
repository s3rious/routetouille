# Contributing to Routetouille

Thank you for your interest in contributing to Routetouille! We welcome contributions from everyone. Please follow these guidelines to help us maintain a high-quality, consistent, and collaborative codebase.

## Getting Started

- **Read the [DEVELOPMENT_GUIDELINES.md](./DEVELOPMENT_GUIDELINES.md)** for detailed coding standards, workflow, and best practices.
- Fork the repository and create a new branch for your feature or bugfix.
- Make small, focused commits with clear messages.
- Ensure your code is easy to read, well-structured, and follows our conventions.

## Code Style & Quality

- Format code with Prettier and fix all linter errors before submitting.
- Write tests for all new features and bug fixes.
- Avoid magic numbers/strings; use named constants.
- Use explicit, descriptive names for variables, functions, and types.
- Prefer immutability and early returns.

## Pull Requests

- Reference related issues in your PR description.
- Do not include generated or build files in your PR.
- Do not add historical comments or change logs in code or PRs.
- Update documentation (including README.md) if your changes affect usage or public APIs.

## Communication

- Be respectful and constructive in all discussions.
- If you have questions, open an issue or start a discussion.
